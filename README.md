# VPS Manager 1.0.0

Интерактивный менеджер Debian 12/13 и Ubuntu 22.04/24.04 для установки и обслуживания 3x-ui/Xray, Reality, каскада RU → EU, сети, сертификатов и безопасности. Все 11 разделов меню подключены к операциям. Изменения выполняются на том VPS, где запущен менеджер; доступ к чужой удалённой панели не заменяет локальный резервный снимок.

## Быстрая установка с GitHub

Подключитесь к VPS по SSH и выполните:

```sh
git clone https://github.com/arsa11/-vps-tools.git
cd -- -vps-tools
sudo sh install.sh
sudo vps-manager
```

Если вы уже вошли как `root`, `sudo` можно убрать. Если Git или Python ещё не установлены, сначала выполните `sudo apt update && sudo apt install -y git python3`.

**Если репозиторий уже скачан**, обновите его и переустановите менеджер:

```sh
cd ~/-vps-tools
git pull
sudo sh install.sh
sudo vps-manager
```

## Установка и запуск

Распакуйте дистрибутив на VPS. Требуется установленный Python 3.10 или новее (входит в заявленные ОС), systemd и root. В Python используются только стандартные библиотеки; чтение существующего netplan-профиля DNS использует системный `python3-yaml`, обычно установленный вместе с netplan.

```sh
cd VPS-Manager
sudo sh install.sh
sudo vps-manager
```

Можно запускать без установки:

```sh
sudo sh vps-manager.sh
```

Установщик копирует исходники в `/opt/vps-manager/releases/<id>`, атомарно переключает `/opt/vps-manager/current` и создаёт `/usr/local/bin/vps-manager`. Он не меняет сеть, firewall или настройки панели. Общие конфигурации хранятся в `/etc/vps-manager`, состояние и копии — в `/var/lib/vps-manager`, события — в `/var/log/vps-manager/events.jsonl`.

## С чего начать

VPS Manager — программа, которая запускается **на самом сервере** и помогает управлять установленными там 3x-ui и Xray, сетью и резервными копиями. Это не VPN-клиент: пользователи подключаются к настроенному серверу через отдельное клиентское приложение.

Если вы вошли как `root`, `sudo` в примерах можно опустить. Для остальных пользователей нужны права sudo. Для возврата из подраздела введите `0`; повторный `0` в главном меню завершит программу. На вопросы с `[y/N]` введите `y` для согласия или нажмите Enter для отказа; в других вопросах используйте варианты, указанные на экране. Не подтверждайте сетевые изменения до проверки доступа во втором SSH-сеансе.

1. Установите менеджер из GitHub командами из раздела «Репозиторий VPS tools» ниже.
2. Запустите `sudo vps-manager diagnose --online` и изучите `WARN` и `ERROR`. Отсутствие IPv6 допустимо, если провайдер его не выдал.
3. Создайте копию: `sudo vps-manager backup`. Сохраните выведенный путь и проверьте его командой `verify` из таблицы ниже.
4. Запустите `sudo vps-manager` и выберите нужный раздел. Если 3x-ui и рабочие подключения уже настроены, сначала изучите текущее состояние и не переустанавливайте панель ради проверки.

Копия содержит конфиденциальные данные. Не публикуйте её, пароль панели, приватные ключи, UUID и VLESS-ссылки. Для опасных операций заранее проверьте доступ к консоли провайдера: автоматический откат реализован, но его работа на конкретном VPS не проверена.

## Пункты главного меню

Число вводится после приглашения `Выбор:`. Меню может запросить дополнительные данные и подтверждение.

| Пункт | Что делает и когда использовать |
| --- | --- |
| **1. Подготовка сервера** | Проверяет состояние и предлагает установить недостающие пакеты; содержит настройку DNS и времени. `APT upgrade` запускается отдельно и не имеет универсального отката. |
| **2. Установка / управление 3x-ui** | Устанавливает выбранный релиз панели, меняет версию и настройки доступа, управляет службой, проверяет или обновляет Xray. Пункт 8 открывает оригинальное интерактивное меню `x-ui`; его действия выполняются средствами самой 3x-ui. На настроенном сервере изменение версии затрагивает работающую панель. |
| **3. Управление IPv4 / IPv6** | Показывает адреса и маршруты, добавляет выданный провайдером адрес и меняет исходящий маршрут. После перезагрузки в этом разделе можно проверить сохранность адреса. |
| **4. Настройка VLESS Reality** | Через API панели создаёт новый inbound и клиентскую ссылку. Нужен свободный порт; существующий порт 443 может уже использоваться. |
| **5. Каскад RU → EU** | На RU-сервере принимает VLESS-ссылку EU-сервера, проверяет соединение и добавляет правила Xray для выбранных inbound. Это не меняет системный маршрут VPS. |
| **6. SSL-сертификаты** | Подключает имеющийся сертификат или запрашивает новый через ACME. Для HTTP-подтверждения нужен доступный извне порт 80. |
| **7. Безопасность VPS** | Показывает текущие правила и порты, предлагает настройки UFW, ограничения доступа к панели, SSH-ключей и Fail2ban. |
| **8. Диагностика** | Общий отчёт, проверка VLESS-соединения и JSON Xray. Общий отчёт доступен без изменения конфигурации. |
| **9. Резервные копии и восстановление** | Создание, список и проверка копий; восстановление и просмотр либо откат транзакций. Восстановление заменяет сохранённые в копии пути. |
| **10. Обновление VPS Manager** | Проверка и установка текущего commit ветки main из GitHub, обновление из проверенного локального архива или настроенного релиза и возврат к предыдущей версии менеджера. После обновления выйдите из программы и запустите её заново. |
| **11. Быстрая настройка нового VPS** | Пошаговый мастер с сохранением прогресса. Отдельные шаги можно выполнить, пропустить или вернуться назад. |
| **0. Назад / выход** | Возврат на предыдущий уровень или выход из главного меню. |

## Справочник команд

Эти команды вводятся в терминале сервера после установки. Команды, открывающие мастера, могут изменять систему после ввода данных и подтверждения.

| Команда | Назначение |
| --- | --- |
| `vps-manager` или `vps-manager menu` | Открыть главное меню. |
| `vps-manager --version` | Показать версию менеджера. |
| `vps-manager diagnose` | Локальная диагностика без внешних проверок. |
| `vps-manager diagnose --online` | Диагностика с проверкой внешнего DNS, HTTPS и IPv4/IPv6. |
| `vps-manager diagnose --online --json --output /root/vps-report.json` | Выполнить внешние проверки и сохранить JSON-отчёт; также вывести JSON на экран. |
| `vps-manager prepare` | Запустить подготовку и мастер установки пакетов. |
| `vps-manager dns` / `vps-manager ntp` | Запустить мастер DNS / синхронизации времени. |
| `vps-manager backup` | Создать резервную копию и вывести её путь. |
| `vps-manager list-backups` | Показать копии и результат их проверки. |
| `vps-manager verify /путь/к/копии` | Проверить манифест и контрольные суммы выбранной копии. |
| `vps-manager restore` | Выбрать копию и запустить мастер восстановления. |
| `vps-manager transactions` | Показать идентификаторы и состояния транзакций. |
| `vps-manager rollback ID` | Запустить откат указанной активной или неудачной транзакции. ID берётся из списка транзакций. |
| `vps-manager network` / `vps-manager network-verify` | Запустить мастер смены IP / проверить сохранённый адрес после перезагрузки. |
| `vps-manager xui` | Запустить мастер установки или смены версии 3x-ui. |
| `vps-manager reality` / `vps-manager routing` | Запустить мастер Reality / каскада. |
| `vps-manager ssl` / `vps-manager security` | Запустить мастер сертификата / настройки UFW. Другие функции безопасности доступны через меню 7. |
| `vps-manager update` / `vps-manager quick-setup` | Запустить мастер обновления менеджера / быструю настройку. |
| `vps-manager install-local` | Установить текущую копию менеджера в системный каталог; это делает и `sh install.sh`. |
| `vps-manager --help` | Показать список команд. |

Например, чтобы проверить конкретную копию, скопируйте путь из вывода `backup` целиком:

```sh
sudo vps-manager backup
sudo vps-manager verify /var/lib/vps-manager/backups/ИМЯ_ИЗ_ВЫВОДА
```

`ИМЯ_ИЗ_ВЫВОДА` — пример, его нужно заменить настоящим именем каталога. Для вывода и проверки копий могут потребоваться права root.

## Как устроен откат

Перед рискованной операцией показывается действие и запрашивается подтверждение. Затем создаётся копия только затрагиваемых путей и устанавливается отдельный systemd timer с абсолютным временем и `Persistent=true`. Он не зависит от SSH-сеанса. Исполнитель отката копируется в приватный каталог транзакции, поэтому обновление программы не меняет уже запланированный откат.

После изменения выполняются проверки. Для сети, firewall и SSH требуется открыть новый сеанс и подтвердить доступ. Без подтверждения таймер останавливает незавершённый процесс применения и его дочерние процессы, восстанавливает файлы и выполняет команды восстановления. При ошибке восстановления systemd повторяет попытку, а состояние остаётся `failed` для диагностики. Новая рискованная операция при незавершённой транзакции блокируется.

```sh
sudo vps-manager transactions
sudo vps-manager rollback ИДЕНТИФИКАТОР
sudo systemctl list-timers 'vps-manager-rollback-*'
```

Не удаляйте каталоги активных транзакций. Для аварийного доступа используйте консоль провайдера. Откат не заменяет снимок диска у провайдера и не может исправить недоступность самого VPS или отказ диска. `apt upgrade` выполняется отдельно и не объявляется обратимой транзакцией.

## Первый запуск панели

При новой установке выберите доступ: **1 — через SSH-туннель** (`127.0.0.1`) или **2 — обычный доступ по IP и порту** (`0.0.0.0`). Во втором случае до настройки сертификата используется HTTP, поэтому пароль передаётся без HTTPS; для доступа извне может понадобиться разрешить выбранный порт в firewall. Существующая установка при обновлении не переключается автоматически.

Панель получает случайный пароль и webBasePath. Данные сохраняются с правами 0600 в `/var/lib/vps-manager/panel-access.json`. Для первого входа используйте SSH-туннель:

```sh
ssh -L 2053:127.0.0.1:2053 root@IP_СЕРВЕРА
```

Откройте локальный URL с путём из файла. Если выбран другой порт, замените 2053. Перед внешней привязкой настройте сертификат. Внешний доступ по HTTP в мастере настроек требует отдельного подтверждения.

API поддерживает cookie-сессию, 2FA и CSRF новых версий 3x-ui. Ввод пароля и VLESS URI скрыт. Настройки Xray сохраняются через `panel/xray/update`, inbound — через `panel/api/inbounds/add`; редактирование сгенерированного `config.json` и прямое изменение таблиц настроек SQLite не используются. Для изменяющих операций URL панели должен разрешаться в локальный адрес этого VPS.

## Сеть и классификация RU

Указывайте только реально выделенный провайдером адрес, точный CIDR и шлюз. `/32` не преобразуется в `/24`. Старые адреса не удаляются автоматически. Пробная таблица сначала проверяет новый источник, не меняя действующий default. Если старый маршрут имеет metric 0, используется отдельная таблица и правила для выбора нового исходящего адреса; ответы со старых локальных адресов сохраняют прежнюю таблицу. Постоянные адреса/маршруты записываются в профиль действующего сетевого менеджера. Неоднозначная существующая policy routing/VPN останавливает автоматический мастер.

Для netplan нужно указать ID из `netplan get`, который может отличаться от имени интерфейса. После плановой перезагрузки выполните:

```sh
sudo vps-manager network-verify
```

Шаблон RU использует `domain:ru`, `domain:su`, `domain:xn--p1ai` и `geoip:ru`. В официальной geosite.dat группа `ru` отсутствует; программа не генерирует неработающее `geosite:ru`. Домены других зон классифицируются по IP после DNS либо добавляются в пользовательские исключения. Это не гарантирует юридическую или организационную принадлежность сайта к стране. Порядок правил выбирается явно: при `last` старое широкое правило может перехватить трафик, при `first` каскад получает приоритет перед прежними правилами выбранных inbound. Системные маршруты VPS при настройке каскада не меняются.

## Сертификаты

Для HTTP-01 нужен доступный извне TCP 80. Менеджер не останавливает занимающий порт сервис автоматически. Выберите существующий сертификат либо предварительно согласуйте освобождение порта. Для IP-сертификатов нужен публичный IP и поддержка профиля `shortlived`; используется раннее продление. Автоматическое продление зависит от доступности CA и порта 80. После смены IP перевыпустите IP-сертификат через раздел SSL.

## Осознанные ограничения

- Поддерживается стандартная локальная установка 3x-ui с SQLite в `/etc/x-ui/x-ui.db` и бинарниками в `/usr/local/x-ui`. Docker, PostgreSQL, перенесённые пути и нестандартные systemd unit не должны автоматически приниматься за такую установку.
- Произвольные версии панели и Xray не гарантированно совместимы. Перед изменением проверяются архив, бинарник и конфигурация; при ошибке восстанавливается согласованная копия. Существующий релиз не заменяется на latest, если запрошенный тег отсутствует.
- Существующие сторонние nftables/iptables конфигурации показываются, но не заменяются UFW. Их автоматическая перестройка без знания политики могла бы заблокировать администратора. Управляйте ими через действующий инструмент.
- Проверка шлюза использует ICMP. Если провайдер его фильтрует, мастер прекращает изменение до смены маршрута; уточните профиль у провайдера.
- Внешний вход по SSH, поведение сети после реальной перезагрузки и доступность ACME извне требуют проверки на конкретном VPS. Локальный тест не выдаётся за такую проверку.
- Исходники опубликованы в **arsa11/-vps-tools**. В меню 10 → 1 можно установить текущие изменения ветки main по конкретному commit через HTTPS; отдельной криптографической подписи релиза при этом нет. Самообновление из локального дистрибутива также работает; для обновления через GitHub нужны опубликованные Releases с архивом и SHA256. После создания таких релизов создайте `/etc/vps-manager/update.json` с полями `repository` (`owner/repo`) и `asset` (`vps-manager.tar.gz`).

## Команды и диагностика

```sh
sudo vps-manager diagnose
sudo vps-manager diagnose --online --json --output /root/vps-report.json
sudo vps-manager backup
sudo vps-manager list-backups
sudo vps-manager verify /var/lib/vps-manager/backups/ИМЯ
sudo vps-manager restore
sudo vps-manager quick-setup
```

Диагностика возвращает код 1 при ERROR. WARN не обязательно означает неисправность: отсутствие IPv6 может быть нормальным. Копии содержат секреты и должны храниться защищённо; права каталогов 0700, файлов 0600. В лог событий попадают названия операций и идентификаторы транзакций, а не пароли или содержимое конфигураций.

## Архитектура и тестирование

`install.sh` и `vps-manager.sh` — оболочки запуска; `modules/*.sh` — отдельные точки входа. Основная логика в `vpsmanager/*.py`: стандартная библиотека Python используется для строгого JSON, безопасных аргументов subprocess, SQLite backup, атомарных файлов и проверяемых транзакций. Это осознанное отличие от предложенных в ТЗ Bash-библиотек; внешние зависимости Python не нужны для основной работы.

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q vpsmanager
python3 build_release.py
```

Дополнительные тесты настоящего Xray включаются переменной `VPS_MANAGER_TEST_XRAY=/путь/к/xray`; для локального TLS-стенда нужен OpenSSL. Тест `tests/systemd_smoke.py` запускайте только в одноразовом systemd-контейнере с `VPS_MANAGER_DISPOSABLE_TEST=1`. GitHub Actions содержит матрицу четырёх ОС и отдельный тест независимого таймера. Факт наличия workflow не означает, что удалённый CI уже выполнялся; результаты текущей проверки перечислены в `ACCEPTANCE.md`.
