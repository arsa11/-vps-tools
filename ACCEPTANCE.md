# Проверка выпуска 1.0.0

Дата: 12 ноября 2026 года.

## Выполнено на текущем компьютере

- 30 автоматических тестов: 29 успешно, 1 пропущен — проверка POSIX-прав, недоступная на Windows.
- Реальные HTTP-тесты API: cookie-сессии старых версий, CSRF новых версий, сохранение параметров шаблона, отказ от передачи пароля по удалённому HTTP, отсутствие секретов в сообщениях об ошибках API.
- Проверка SQLite online backup при активном WAL, точного восстановления, удаления добавленных после снимка файлов, сохранения отсутствующего пути, отказа при повреждении контрольной суммы и опасном манифесте.
- Проверка порядка отката, повторного вызова, отказа подтверждать истёкшую транзакцию и сохранения состояния для повторной попытки при ошибке восстановления. В этих тестах systemd-команды заменены контролируемыми имитациями.
- Проверка безопасной распаковки, отказа от path traversal и ссылок в дистрибутиве, запрета незаметной подмены отсутствующего релиза другой версией.
- Проверка VLESS-параметров, несовместимого flow/transport, адресов/CIDR и повторного построения каскада без дубликатов.
- Официальный Xray **26.11.9 для Windows**: валидация Reality inbound/outbound, gRPC и RU-каскада с официальной geoip.dat.
- Сквозной тест настоящего Reality: локальный TLS target → Xray server → Xray client/SOCKS → локальный HTTP origin; ответ получен через туннель. Использованы временные ключи, только localhost, без доступа к реальному VPS. Для нового защитного механизма Xray в тестовом outbound разрешён исключительно локальный порт тестового HTTP origin; в рабочие конфигурации это разрешение не добавляется.
- Статический анализ pyflakes, компиляция Python и проверка Bash-синтаксиса установщика, основного запуска и модульных оболочек.

## Подготовлено, но здесь не выполнялось

В `.github/workflows/tests.yml` есть проверки Debian 12/13 и Ubuntu 22.04/24.04, а также отдельный Docker/systemd тест. В текущей среде нет Linux/systemd, WSL или Docker, поэтому запуск workflow и настоящий systemd timer здесь не проводились.

`tests/systemd_smoke.py` проверяет настоящий независимый таймер, завершение процесса применения, восстановление файла и отмену таймера после commit. Этот сценарий предназначен исключительно для одноразового Linux-контейнера с явным флагом `VPS_MANAGER_DISPOSABLE_TEST=1`.

## Проверки на конкретном VPS

Перед эксплуатацией нужны проверка реальной установки выбранной версии 3x-ui, доступ по SSH после смены IP/firewall, автоматический откат при разрыве SSH, устойчивость после перезагрузки, маршрутизация RU/EU через внешнего клиента и выпуск/продление ACME. Они зависят от сети и политик провайдера, конфигурации служб и выбранных версий. Этот выпуск не обозначает эти проверки как выполненные.

## Сверка интерфейсов

При реализации использованы официальные источники:

- https://github.com/MHSanaei/3x-ui — CLI, API inbound, Xray settings, cookie и CSRF; сверены исходники v2.8.5 и текущей основной ветки.
- https://github.com/XTLS/Xray-core — официальный проверочный бинарник и конфигурации.
- https://xtls.github.io/en/config/outbounds/freedom.html — безопасные finalRules в новых версиях Xray.
- https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability — короткоживущие IP-сертификаты.
- https://github.com/acmesh-official/acme.sh — параметры выпуска и продления.
- https://netplan.readthedocs.io/ — маршруты и source address.
- https://networkmanager.dev/docs/api/1.38/nm-settings-nmcli.html — атрибуты маршрутов NetworkManager.

## Отличия от предложенной архитектуры ТЗ

Внешние точки входа — shell-скрипты, а транзакционное ядро — Python 3 со стандартной библиотекой. Это позволяет использовать штатный SQLite backup и валидировать JSON/архивы без небезопасной интерполяции shell. Внешний официальный репозиторий проекта не выдуман: обновление работает из локального архива, а GitHub-источник настраивается после публикации проекта.
